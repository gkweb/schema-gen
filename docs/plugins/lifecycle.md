# Plugin Lifecycle

schema-gen executes plugins through a 6-phase lifecycle. Understanding these phases helps you build effective plugins.

## Lifecycle Overview

```
┌──────────────────────────────────────────────────────────┐
│  Phase 1: onStart                                        │
│  - Plugin initialization                                 │
│  - Setup, logging, shared state initialization           │
├──────────────────────────────────────────────────────────┤
│  Phase 2: AST Hooks (onType, onEnum, onEndpoint)        │
│  - Filter or modify AST nodes                            │
│  - Return null to exclude, return modified node,         │
│    or void to keep unchanged                             │
├──────────────────────────────────────────────────────────┤
│  Phase 3: emit                                           │
│  - Generate output files                                 │
│  - Main code generation phase                            │
├──────────────────────────────────────────────────────────┤
│  Phase 4: onFile                                         │
│  - Post-process generated files                          │
│  - Format, validate, or transform file content           │
├──────────────────────────────────────────────────────────┤
│  Phase 5: onEnd                                          │
│  - Cleanup after all plugins emit                        │
│  - Final state processing                                │
├──────────────────────────────────────────────────────────┤
│  Phase 6: onFinished                                     │
│  - Called after files are written to disk                │
│  - Post-write hooks (e.g., run formatter, notify)        │
└──────────────────────────────────────────────────────────┘
```

## Phase 1: onStart

Called once before processing begins. Use for initialization.

```ts
definePlugin({
  // ...
  async onStart(ctx) {
    ctx.log.info('Starting code generation...');
    ctx.shared.set('startTime', Date.now());

    // Validate configuration
    if (!ctx.config.apiPrefix) {
      ctx.log.warn('No apiPrefix configured, using default');
    }
  },
});
```

**Use cases:**
- Initialize shared state
- Validate configuration
- Log startup messages
- Pre-compute data used in later phases

## Phase 2: AST Hooks

Called for each AST node. Return values control filtering/modification.

### onType

```ts
definePlugin({
  // ...
  onType(node, ctx) {
    // Filter out internal types
    if (node.name.startsWith('_')) {
      return null; // Exclude this type
    }

    // Modify a type
    if (node.name === 'User') {
      return {
        ...node,
        properties: [
          ...node.properties,
          {
            name: 'fullName',
            typeRef: { kind: 'primitive', primitiveType: 'string' },
            required: false,
          },
        ],
      };
    }

    // Return void or undefined to keep unchanged
  },
});
```

### onEnum

```ts
definePlugin({
  // ...
  onEnum(node, ctx) {
    // Add a "Unknown" variant to all enums
    return {
      ...node,
      variants: [
        ...node.variants,
        { name: 'Unknown', value: 'unknown' },
      ],
    };
  },
});
```

### onEndpoint

```ts
definePlugin({
  // ...
  onEndpoint(node, ctx) {
    // Skip deprecated endpoints
    if (node.deprecated) {
      return null;
    }

    // Only include public API endpoints
    if (!node.tags.includes('public')) {
      return null;
    }

    return node;
  },
});
```

**Return values:**
- `null` - Filter out the node
- Modified node - Replace with modified version
- `void` / `undefined` - Keep unchanged

## Phase 3: emit

Called once after AST hooks. Generate output files here.

```ts
definePlugin({
  // ...
  async emit(ctx) {
    const files: GeneratedFile[] = [];

    // Generate a file for each tag
    for (const tag of ctx.ast.tags) {
      const endpoints = ctx.utils.getEndpointsByTag(tag.name);

      if (endpoints.length === 0) continue;

      const content = generateCodeForEndpoints(endpoints);

      files.push({
        path: `${ctx.utils.toKebabCase(tag.name)}.ts`,
        content,
      });
    }

    return files;
  },
});
```

**Key points:**
- Return an array of `GeneratedFile` objects
- Each file has `path` and `content` properties
- Paths are relative to `output.dir`
- Can be async

## Phase 4: onFile

Called for each generated file (from all plugins). Post-process files here.

```ts
definePlugin({
  // ...
  async onFile(file, ctx) {
    // Add a header to all TypeScript files
    if (file.path.endsWith('.ts')) {
      return {
        ...file,
        content: `// Generated by ${ctx.ast.info.title}\n\n${file.content}`,
      };
    }

    // Filter out test files
    if (file.path.includes('.test.')) {
      return null;
    }

    // Keep unchanged
    return file;
  },
});
```

**Use cases:**
- Add headers/footers to files
- Format code
- Validate generated content
- Filter out files
- Transform file paths

## Phase 5: onEnd

Called once after all plugins have emitted. Use for cleanup.

```ts
definePlugin({
  // ...
  async onEnd(ctx) {
    const startTime = ctx.shared.get('startTime') as number;
    const duration = Date.now() - startTime;
    ctx.log.info(`Generation completed in ${duration}ms`);

    // Clean up shared state
    ctx.shared.delete('startTime');
  },
});
```

**Use cases:**
- Log completion messages
- Clean up shared state
- Aggregate statistics

## Phase 6: onFinished

Called once after files are written to disk. Has access to written file info.

```ts
definePlugin({
  // ...
  async onFinished(ctx) {
    ctx.log.info(`Wrote ${ctx.files.length} files:`);

    for (const file of ctx.files) {
      ctx.log.info(`  - ${file.relativePath}`);
    }

    // Run external tool on generated files
    // await exec('prettier --write', ctx.files.map(f => f.absolutePath));
  },
});
```

**Context extension:**
```ts
interface FinishedContext extends PluginContext {
  files: WrittenFile[];
}

interface WrittenFile {
  absolutePath: string;
  relativePath: string;
  content: string;
}
```

**Use cases:**
- Log written files
- Run formatters/linters
- Trigger external processes
- Send notifications

## Execution Order

1. All plugins run `onStart` in order
2. For each node type:
   - All plugins run `onType` (types mutate through chain)
   - All plugins run `onEnum`
   - All plugins run `onEndpoint`
3. All plugins run `emit` in order
4. For each file (all files from all plugins):
   - All plugins run `onFile` (files mutate through chain)
5. All plugins run `onEnd` in order
6. Files are written to disk
7. All plugins run `onFinished` in order

## Example: Full Plugin

```ts
import { definePlugin, type Plugin, type PluginContext } from '@schema-gen/plugin-sdk';

export interface StatsPluginConfig {
  outputFile?: string;
}

export function statsPlugin(config?: StatsPluginConfig): Plugin {
  const outputFile = config?.outputFile ?? 'stats.json';
  let stats = {
    types: 0,
    enums: 0,
    endpoints: 0,
    files: 0,
  };

  return {
    id: 'stats',
    name: 'Statistics Plugin',
    version: '1.0.0',

    onStart(ctx) {
      ctx.log.info('Collecting API statistics...');
      stats = { types: 0, enums: 0, endpoints: 0, files: 0 };
    },

    onType(node) {
      stats.types++;
      return node;
    },

    onEnum(node) {
      stats.enums++;
      return node;
    },

    onEndpoint(node) {
      stats.endpoints++;
      return node;
    },

    emit(ctx) {
      return [
        {
          path: outputFile,
          content: JSON.stringify({
            api: ctx.ast.info.title,
            version: ctx.ast.info.version,
            stats,
          }, null, 2),
        },
      ];
    },

    onFile(file) {
      stats.files++;
      return file;
    },

    onEnd(ctx) {
      ctx.log.info(`Stats: ${stats.types} types, ${stats.enums} enums, ${stats.endpoints} endpoints`);
    },

    onFinished(ctx) {
      ctx.log.info(`Wrote ${ctx.files.length} files`);
    },
  };
}
```
